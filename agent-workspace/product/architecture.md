# Nerv Architecture

## Architecture principle

Nerv is local-first.

It lives inside the developer's repo and keeps local state in `.nerv/`.

## Source of truth

SQLite is the source of truth for work state.

```txt
.nerv/nerv.db
```

It stores:

- Agentic Builds
- Agentic Tasks
- Runs
- Checkpoints
- Reviews
- Decisions
- Relationships
- Status history
- Related files
- Git metadata

## Markdown role

Markdown has two roles.

### 1. Stable human documentation

These files are editable by humans:

```txt
.nerv/product/*.md
.nerv/repo/development.md
```

### 2. Agent-facing generated context

These files are generated or regenerated by Nerv:

```txt
.nerv/agent/runs/RUN-001/run.md
.nerv/agent/runs/RUN-001/task.md
.nerv/agent/builds/BUILD-001.md
```

## Agent entrypoint

The agent should use one entrypoint:

```txt
.nerv/agent/runs/RUN-001/run.md
```

The `run.md` file tells the agent:

- Which task is active
- What the scope is
- Which context files to read
- Which commands to run
- How to checkpoint
- How to review
- How to close

## Scope rule

The Agentic Task is the execution scope.

The Agentic Build is shared context, not additional scope.

If the Task and Build conflict, the Task wins.

## Git role

Git stores code history.

Nerv stores work history.

A task should normally be committed after review and before close.

```txt
checkpoint = save work memory
review = verify readiness
commit = save stable code state
close = close Nerv task and link commit
```
