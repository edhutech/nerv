# TASK-012: Implement Agentic Build Creation And Planning

## Status

Closed

## Parent Build

BUILD-004

## Task Goal

Implement `nerv new build "..."` and `nerv build plan BUILD-001` so larger intent can become a stored Agentic Build and then be broken into scoped Agentic Tasks.

## Why this task matters

Builds help Nerv keep broad goals as context while preserving Agentic Tasks as the execution scope. This lets developers plan meaningful chunks without asking a coding agent to build everything at once.

## Context

BUILD-004 requires build-to-task relationships and basic generated build and task Markdown where useful. DEC-008 says build creation must be confirmed before task planning when `nerv new task` detects oversized intent.

## Scope

This task includes:

- Replace the `nerv new build` placeholder with real command behavior.
- Require an initialized Nerv workspace before creating builds.
- Generate stable `BUILD-###` IDs using existing ID helpers.
- Store build intent, title, status and basic planning fields in SQLite.
- Generate basic build Markdown where useful.
- Implement `nerv build plan BUILD-001` with deterministic MVP task suggestions.
- Persist planned tasks and link them to the selected build.
- Preserve the rule that a Task is execution scope and Build context must not override Task scope.
- Add smoke coverage for build creation, planning and persisted relationships.

## Out of scope

This task does not include:

- Automatic AI planning.
- Complex estimation or prioritization.
- Team workflows.
- Run generation or `nerv start`.
- Review, checkpoint or close lifecycle behavior.
- Rich interactive planning sessions.

## Acceptance criteria

This task is complete when:

- `nerv new build "..."` creates a stored build with a stable sequential ID.
- `nerv build plan BUILD-001` creates practical linked tasks for the selected build.
- Planned tasks are queryable by their build relationship.
- Build Markdown, if generated, clearly presents build context and does not expand task execution scope.
- Task Markdown, if generated during planning, includes scoped task sections and references the parent build.
- Planning is deterministic and honest about being heuristic, not AI-generated.
- Smoke tests cover build creation, build planning and relationship persistence.

## Validation

Run or verify:

- `pnpm build`
- `pnpm typecheck`
- `pnpm smoke`
- Manual run of `nerv init`, `nerv new build "..."` and `nerv build plan BUILD-001` in a temporary repo.
- Manual SQLite inspection showing a build with linked task rows.

## Risks

- Heuristic task planning can produce bland or overconfident tasks if the generated text is too ambitious.
- Re-running `build plan` may duplicate tasks unless idempotency is explicitly handled.
- Build context can accidentally become scope; generated content should repeat the Task-wins rule.

## Agent instructions

Work only within this task scope.

Do not implement AI planning or run generation. Keep the planning algorithm deterministic and modest. Decide and document whether `build plan` is idempotent, append-only or guarded when tasks already exist.
